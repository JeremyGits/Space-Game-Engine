🏛️ Architecture Overview

Understanding the Space Game Engine's design and structure

High-Level Architecture

The Space Game Engine is built on a modular, layered architecture that separates concerns and promotes maintainability, scalability, and testability.

🎮 Game Layer

Game-specific code, entities, and systems

  • src/game/ - Game entities, systems, configuration
  • src/components/ - React UI components
  • src/store/ - Application state management

🎯 Engine Layer

Core engine systems and functionality

  • src/engine/core/ - ECS, game loop, scene management
  • src/engine/rendering/ - Rendering pipeline
  • src/engine/physics/ - Physics simulation
  • src/engine/input/ - Input handling
  • src/engine/player/ - Player controllers

🛠️ Utility Layer

Reusable utilities and helpers

  • src/utils/math/ - Math utilities (vectors, matrices, quaternions)
  • src/utils/time/ - Time management (clock, timer, stopwatch)
  • src/utils/geometry/ - Geometric primitives (AABB, Sphere)

📚 External Libraries

Third-party dependencies

  • React - UI framework
  • Three.js - 3D rendering
  • React Three Fiber - React renderer for Three.js
  • Rapier - Physics engine
  • Zustand - State management

Core Design Patterns

1. Entity Component System (ECS)

The engine uses an ECS architecture for game object management:

Entities

Lightweight identifiers for game objects. An entity is just an ID with associated components.

// Create an entity
const entity = entityManager.createEntity();

// Add components
entity.addComponent(new TransformComponent());
entity.addComponent(new VelocityComponent());

Components

Pure data containers with no logic. Components store state.

class TransformComponent extends Component {
  position: Vector3;
  rotation: Quaternion;
  scale: Vector3;
  
  constructor() {
    super();
    this.position = new Vector3(0, 0, 0);
    this.rotation = new Quaternion();
    this.scale = new Vector3(1, 1, 1);
  }
}

Systems

Logic processors that operate on entities with specific component combinations.

class PhysicsSystem extends System {
  update(deltaTime: number) {
    // Query entities with Transform and Velocity components
    const entities = this.query(['Transform', 'Velocity']);
    
    for (const entity of entities) {
      const transform = entity.getComponent(TransformComponent);
      const velocity = entity.getComponent(VelocityComponent);
      
      // Apply physics
      transform.position.add(velocity.value.multiplyScalar(deltaTime));
    }
  }
}

2. Module System

The engine is organized into independent modules that can be initialized, updated, and shut down independently:

class GameEngine {
  private modules: Map;
  
  registerModule(name: string, module: Module) {
    this.modules.set(name, module);
    module.initialize();
  }
  
  update(deltaTime: number) {
    for (const module of this.modules.values()) {
      module.update(deltaTime);
    }
  }
}

3. Event-Driven Architecture

Components communicate through an event system, reducing coupling:

// Subscribe to events
eventEmitter.on('collision', (data) => {
  console.log('Collision detected:', data);
});

// Emit events
eventEmitter.emit('collision', {
  entityA: entity1,
  entityB: entity2,
  point: collisionPoint
});

4. Object Pooling

Frequently created/destroyed objects use pooling to reduce garbage collection:

class EntityPool {
  private pool: Entity[] = [];
  
  acquire(): Entity {
    return this.pool.pop() || new Entity();
  }
  
  release(entity: Entity) {
    entity.reset();
    this.pool.push(entity);
  }
}

Game Loop Architecture

The engine uses a fixed timestep game loop with separate update and render phases:

class GameLoop {
  private readonly FIXED_TIMESTEP = 1 / 60; // 60 Hz
  private accumulator = 0;
  
  tick(deltaTime: number) {
    this.accumulator += deltaTime;
    
    // Fixed update (physics)
    while (this.accumulator >= this.FIXED_TIMESTEP) {
      this.fixedUpdate(this.FIXED_TIMESTEP);
      this.accumulator -= this.FIXED_TIMESTEP;
    }
    
    // Variable update (game logic)
    this.update(deltaTime);
    
    // Render
    this.render(this.accumulator / this.FIXED_TIMESTEP);
  }
}

Loop Phases

1. Early Update

Input processing and event handling

  • Process keyboard/mouse/gamepad input
  • Update input state
  • Handle UI events

2. Fixed Update

Physics simulation at fixed 60 Hz

  • Apply forces and velocities
  • Detect and resolve collisions
  • Update physics bodies

3. Update

Game logic at variable framerate

  • Update game state
  • Process AI
  • Handle game events

4. Render

Drawing to screen

  • Update camera
  • Render 3D scene
  • Draw UI
  • Apply post-processing

State Management

The engine uses Zustand for application state management with a modular store architecture:

// Game store
export const useGameStore = create((set) => ({
  player: null,
  entities: [],
  currentMission: null,
  
  updatePlayer: (player) => set({ player }),
  addEntity: (entity) => set((state) => ({
    entities: [...state.entities, entity]
  }))
}));

// UI store
export const useUIStore = create((set) => ({
  showHUD: true,
  showMenu: false,
  
  toggleHUD: () => set((state) => ({ showHUD: !state.showHUD }))
}));

Store Middleware

  • Persist Middleware - Saves state to localStorage
  • Logger Middleware - Logs state changes for debugging
  • Devtools Middleware - Redux DevTools integration

Performance Considerations

Optimization Strategies

GPU Instancing

Render thousands of similar objects with a single draw call:

// Render 40,000+ grass blades efficiently
const grassRenderer = new GrassRenderer({
  density: 8,
  areaSize: 70,
  bladeHeight: 0.15
});

grassRenderer.generateGrassField();

Level of Detail (LOD)

Use simpler models for distant objects:

const lodManager = new LODManager();
lodManager.addLevel(highDetailMesh, 0, 50);
lodManager.addLevel(mediumDetailMesh, 50, 100);
lodManager.addLevel(lowDetailMesh, 100, 200);

Frustum Culling

Only render objects visible to the camera:

const frustumCuller = new FrustumCuller(camera);
const visibleEntities = frustumCuller.cull(allEntities);

Object Pooling

Reuse objects instead of creating/destroying:

const bulletPool = new EntityPool(Bullet, 100);

// Acquire from pool
const bullet = bulletPool.acquire();

// Release back to pool when done
bulletPool.release(bullet);

Coordinate System

The engine uses a right-handed coordinate system consistent with Three.js:

/**
 * COORDINATE SYSTEM:
 * - Forward (North): -Z axis
 * - Right (East): +X axis
 * - Up: +Y axis
 * 
 * ROTATION:
 * - Pitch: Rotation around X axis (look up/down)
 * - Yaw: Rotation around Y axis (look left/right)
 * - Roll: Rotation around Z axis (tilt)
 */

This coordinate system is used consistently throughout the engine, including:

  • FirstPersonController
  • Camera systems
  • Physics calculations
  • Transform components

Extension Points

The engine is designed to be extended. Key extension points include:

Custom Components

class HealthComponent extends Component {
  health: number = 100;
  maxHealth: number = 100;
  
  takeDamage(amount: number) {
    this.health = Math.max(0, this.health - amount);
  }
}

Custom Systems

class HealthSystem extends System {
  update(deltaTime: number) {
    const entities = this.query(['Health']);
    
    for (const entity of entities) {
      const health = entity.getComponent(HealthComponent);
      
      if (health.health <= 0) {
        this.handleDeath(entity);
      }
    }
  }
}

Custom Materials

class HologramMaterial extends CustomMaterial {
  constructor() {
    super({
      vertexShader: hologramVertexShader,
      fragmentShader: hologramFragmentShader,
      uniforms: {
        time: { value: 0 },
        color: { value: new THREE.Color(0x00ffff) }
      }
    });
  }
}

Best Practices

Separation of Concerns

  • Keep game logic separate from engine code
  • Components should only contain data, not logic
  • Systems should be focused on a single responsibility

Performance

  • Use object pooling for frequently created objects
  • Implement LOD for complex models
  • Profile regularly with PerformanceMonitor
  • Batch similar draw calls

Code Organization

  • Follow the established directory structure
  • Use TypeScript interfaces for public APIs
  • Document complex algorithms
  • Write unit tests for critical systems
